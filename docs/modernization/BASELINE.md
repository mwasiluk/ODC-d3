## 2. Isolation method

The build overwrites a tracked source file (`src/d3.js`, see §4.1), so it was
never run in the repository checkout. Instead:

```bash
git archive a937bcebf0bc9d89ba78843e0815e8289767fc30 | tar -x -C <scratch>/work
cd <scratch>/work && git init -q && git add -A && git commit -qm baseline   # for diffing only
```

All commands in §3 ran inside that copy. The repository checkout was not
built and its `package-lock.json` was not modified (sha256 verified before and
after `npm ci`).

## 4. Build behaviour

### 4.1 The build rewrites `src/d3.js`

`src/d3.js` is a tracked file whose committed content is identical to
`src/d3_import.js` (re-exports of the bundled `d3-*` packages). `gulp build-js`:

1. `copy-global-d3`: copies `src/d3_global.js` (`module.exports = d3`) over `src/d3.js`,
2. browserifies `src/index.js` → `dist/odc-d3.js` (global-D3 bundle),
3. copies `src/d3_import.js` back over `src/d3.js`.

`build-js-standalone` bundles with the import variant → `dist/standalone/odc-d3.js`.

Consequences, all confirmed in §3:

- After a **successful** run `src/` is clean.
- After an **interrupted** run (#7) `src/d3.js` stays in the global variant.
  A following `build-js-standalone` would then silently produce a "standalone"
  bundle that requires global D3.
- The swap is not safe to run concurrently with an editor/IDE watcher or a second build.

### 4.2 Errors do not fail the build

`map_error` (browserify) and `onError` (gulp-plumber) both log and call
`this.emit('end')`. Every JS/SCSS compile error ends with exit code 0 (#4–#6),
and `default` additionally deletes the previous `dist/` first (#5). CI or a
release script cannot rely on the exit code at this baseline; it must verify
the output files.

- `dist/*.js` (non-minified) contain an inline base64 source map (`debug: true`), which is why they are 2–3 MB. `*.min.js` reference external `.map` files.
- `gulp-strip-debug` removes `console.*`/`debugger` only from `*.min.js`.
- CSS: all `src/styles/*` compiled and concatenated in alphabetical file order into one file.

## 6. Dependency state (not changed in this PR)

- `package-lock.json` is **lockfileVersion 1** with stale metadata
  (`"version": "1.1.8"` vs `package.json` `2.0.0`). npm 10 accepts it for `npm ci`
  and leaves it untouched, but any `npm install` would rewrite it to v3.
- The lockfile resolves several D3 v1/v2-era transitive packages at top level,
  and these end up in the bundles:
  `d3-color@1.2.3`, `d3-interpolate@1.3.2`, `d3-time@1.0.10`,
  `d3-time-format@2.1.3`, `d3-timer@1.0.9` (only `d3-scale` has a nested

  direct dependency, so in the standalone bundle `d3.timeFormat`/`d3.timeParse`
  (used by `HeatmapTimeSeries`) come from `d3-time-format@2.1.3`, while the
  global bundle uses the page's D3 v7.
- `d3-format` and `d3-dispatch` are pinned exactly (`3.0.1`), as are
  `d3-selection@3.0.0` and `odc-d3-svg-legend@3.0.0`. Everything else uses `^`.
- devDependencies by inspection: `tsify` and `merge-stream` are `require`d in
  `gulpfile.js` but never used; `conditionalify` is not referenced at all;
  `gulp-babel` is used by `build-js2` but is not a dependency.

## 7. Contracts to preserve

These are the observable behaviours later PRs must keep (or change only
deliberately, with a changelog entry).

### 7.1 npm API and deep imports

- `main: "src/index.js"` – untranspiled ES2015+ modules with class fields,
  extensionless relative imports and mixed ESM/CJS (`statistics-utils.js` uses
  `import` **and** `module.exports`). Not loadable by plain Node (#12).
  Consumers need a bundler with Babel. The `browserify.transform` field
  applies babelify to this package for browserify consumers, but `babelify`
  and the presets are devDependencies, so that only works if the consumer
  installs them.
- No `exports`, `module`, `browser`, `types` or `files` field → **every file is a
  public deep import**, e.g. `odc-d3/src/scatterplot`, `odc-d3/src/utils`,
  `odc-d3/dist/odc-d3.min.js`, `odc-d3/dist/standalone/odc-d3.min.js`,
  `odc-d3/dist/odc-d3.min.css`.
- Named exports of `src/index.js` (27, identical in both bundles):
  `BarChart, BarChartConfig, BoxPlot, BoxPlotBase, BoxPlotBaseConfig,
  BoxPlotConfig, CorrelationMatrix, CorrelationMatrixConfig,
  DivergingStackedBarChart, DivergingStackedBarChartConfig, Heatmap,
  HeatmapConfig, HeatmapTimeSeries, HeatmapTimeSeriesConfig, Histogram,
  HistogramConfig, Legend, LineChart, LineChartConfig, Regression,
  RegressionConfig, ScatterPlot, ScatterPlotConfig, ScatterPlotMatrix,
  ScatterPlotMatrixConfig, StatisticsUtils, Utils`.
- Not exported but reachable by deep import: `Chart`, `ChartConfig`,
  `ChartWithColorGroups(Config)`, `D3Extensions`, `tdistr` etc.
- Importing `src/index.js` has a **side effect**: `D3Extensions.extend()` (§7.5).

### 7.2 Global `ODCD3`

Both bundles are browserify UMD (`standalone: 'ODCD3'`): CommonJS
`module.exports`, AMD `define([])`, else `window.ODCD3`. The README documents
only the script-tag usage.

### 7.3 The two bundles

| | `dist/odc-d3(.min).js` | `dist/standalone/odc-d3(.min).js` |
|---|---|---|
| D3 | global `d3` (v7) **must be loaded first**, read at load time | bundled `d3-*` from the lockfile |
| `src/d3.js` used | `module.exports = d3` | `src/d3_import.js` re-exports |
| Still bundled | `d3-array, d3-color, d3-dispatch, d3-format, d3-interpolate, d3-scale, d3-selection, d3-time, d3-time-format, internmap` (pulled in by `odc-d3-svg-legend`), `simple-statistics`, `@babel/runtime` | all of the left plus `d3-axis, d3-brush, d3-drag, d3-ease, d3-hierarchy, d3-path, d3-scale-chromatic, d3-shape, d3-timer, d3-transition` |
| Prototype extensions applied to | the page's global `d3.selection` | the bundled `d3-selection` only |

The global bundle therefore contains a second copy of `d3-selection` used by
the legend, next to the page's D3. The D3 namespace object is also a
configuration contract: `Utils.createScale(name)` calls `d3['scale' + Name]()`
and `Utils.createAxis(orient)` calls `d3['axis' + Orient]()`, so the set of
names re-exported by `src/d3.js` (or present on global `d3`) defines which
`scale`/`orient` config strings work.

### 7.4 CSS, configuration and chart lifecycle

- CSS: `dist/odc-d3.css` / `.min.css`, one file for all charts. Class prefix
  `odc-` (`ChartConfig.cssClassPrefix`); per-chart svg classes `odc-scatterplot`,
  `odc-scatterplot-matrix`, `odc-correlation-matrix`, `odc-heatmap` (hard-coded,
  ignores the prefix), `odc-histogram`, `odc-bar-chart`, `odc-box-plot`,
  `odc-diverging-stacked-bar-chart`, `odc-line-chart`; base `odc-mw-d3-chart`.
  Shared: `.odc-tooltip` (a `div` appended to `body`), `.odc-legend`,
  `.odc-axis`, `.odc-dot`, `.odc-bar`, `.odc-cell`, `.odc-selectable`, legend
  `.cell`, `.legendCells`.
- Config: `XxxConfig` classes with class-field defaults; `new XxxConfig(custom)`
  deep-merges `custom` via `Utils.deepExtend` (objects merged, arrays and
  functions replaced). A chart accepts either a plain object or a Config
  instance. Inheritance: `ChartConfig` → `ChartWithColorGroupsConfig` →
  `ScatterPlotConfig` → `RegressionConfig` / `ScatterPlotMatrixConfig`, etc.
- Construction: `new Chart(container, data, config)` where container is a
  selector / DOM node, or another `Chart` (attached mode, draws into the
  parent's svg). The constructor immediately runs `setConfig → setData → init
  → postInit`, i.e. **renders synchronously**.
- `init()` = `initPlot → initSvg → initTooltip (first time) → draw → update`.
  The first init removes any existing `svg` in the container.
- Public lifecycle: `setConfig(cfg)` (re-wraps in the chart's Config class,
  chainable, does not redraw), `setData(d)`, `init()`, `redraw()`,
  `update(data)`, `draw(data)`, `destroy()` (removes all children of the
  container and the `resize.<id>` window listener), `attach(name, chart)`,
  events `on/once/off/trigger` (`cell-selected` on Heatmap and CorrelationMatrix).
- `$`-accessors: for every own config key, `chart.$key()` gets and
  `chart.$key(v)` sets (returns the chart). Nested objects get accessors on the
  accessor function: `chart.$x.$key()` / `chart.$x.$key(v)` (returns the
  chart). Rebuilt by `setConfig` and `redraw`.
- A `resize.<guid>` listener is registered on `window` for every chart where
  `!config.width || config.height` and re-runs `init()` without transitions.
- Transitions are on by default (`config.transition = true`) and are skipped
  on the first render.

### 7.5 D3 prototype extensions

`D3Extensions.extend()` (run on import of `src/index.js`) assigns
`insertSelector`, `appendSelector`, `selectOrAppend`, `selectOrInsert` to
`d3.selection.prototype` **and** `d3.selection.prototype.enter.prototype`
(the latter is the `selection.enter` function object's prototype, not the
enter-selection prototype). Semantics: selector strings like `g.main-group#id`
are split into tag + classes + id. Chart code calls them as selection
methods at 57 places (plus 4 `Utils.selectOrAppend` calls). In the global
build this mutates the page's D3 for all other code on the page.

### 7.6 simple-statistics

`StatisticsUtils` deep-requires CommonJS files from `simple-statistics@4.1.1`:
`src/sample_correlation`, `linear_regression`, `linear_regression_line`,
`error_function`, `standard_deviation`, `sample_standard_deviation`,
`variance`, `mean`, `z_score`, `quantile` (these paths do not exist as CJS in
later majors). Plus local `standardError = sqrt(variance / (n - 1))` and
`tValue(df, p)` from `src/statistics-distributions.js`.

Golden values measured on the committed standalone bundle in Node:

| `linearRegressionLine({m:2,b:1})(3)` | `7` |
| `sampleCorrelation([1,2,3,4],[2,3,5,4])` | `0.7999999999999999` |

### 7.7 odc-d3-svg-legend

Fork of `d3-svg-legend`, pinned to `3.0.0`. Browserify resolves its `main`
(`indexRollup.js`, CJS) which `require`s `d3-array, d3-dispatch, d3-format,
d3-scale, d3-selection` – always bundled, even in the global build
(`d3-transition` is a declared dependency of the fork but not required by
`indexRollup.js`). `Legend` exposes `legendColor`, `legendSize`,
`legendSymbol` as instance fields `color`, `size`, `symbol`. Used by
ChartWithColorGroups, Heatmap, CorrelationMatrix and DivergingStackedBarChart.

## 8. Defects observed (not fixed here)

1. Build exits 0 on JS and SCSS errors (§4.2); `default` deletes `dist/` first.
2. Interrupted build leaves `src/d3.js` mutated (§4.1).
3. `watch`, `serve`, `default-watch`, `build-js2` are broken (§3 #8, #9).
4. `statistics-distributions.js` `max()`/`min()` loop over `$i` but test the
   undeclared `i` → `tValue` throws for df ≤ 3. Effect: `Regression` with
   confidence bands fails for any group with ≤ 5 points (`df = n - 2`).
5. `tValue(df, 0.975)` returns a negative value, so `Regression`'s margin of
   error is negative (bands are drawn with up/down swapped). Documented
   behaviour; changing it changes results.
6. `Chart.prefixClass(clazz, addDot)` has an operator-precedence bug
   (`addDot ? '.' : '' + prefix + clazz` returns just `'.'` when `addDot` is true).
7. `Chart.initSvg`: condition `!config.width || config.height` (probably meant
   `!config.width || !config.height`).
8. `examples/heatmap-timeseries` is broken (§5).
9. README still documents D3 4.x/3.x and `1.x`; nothing says `2.x` needs D3 v7.
10. `package-lock.json` metadata says `1.1.8`, lockfile v1 (§6).
11. Production `npm audit`: `d3-color@1.2.3` (high, ReDoS) and
    `@babel/runtime@7.15.4` (moderate) are shipped inside the bundles.

## 9. Blockers

None of the blockers stopped this baseline:

- **CDN blocked in this environment** (`d3js.org`, `cdn.jsdelivr.net`): worked
  around by serving `d3@7.9.0` from the npm registry in the smoke harness
  (`D3_FILE`). The minimal fix for CI is the same: install D3 as a test-only
  devDependency, or keep the routing in the harness.
- **No test runner and no DOM library in devDependencies**: the browser checks
  used the Playwright copy pre-installed in the container. A following PR must
  add Playwright (Chromium) and a test runner explicitly (that is a lockfile
  change and belongs to that PR).
- **Build exit code is unreliable**: every automated check has to verify
  output files until §8.1 is fixed.

## 10. Minimal test set for the next PR

Goal: lock the contracts in §7 before any dependency or build change. Run
against the committed `dist/` and against a fresh build.

1. **Build integrity script** (no new deps): run `gulp` in a temp copy and
   assert that all 8 `dist/` files exist and are non-empty, `git diff --quiet
   src` holds afterwards, and generated code equals the committed files
   (ignoring `sourcesContent` line endings). Include the cases from §3 #4–#6 as
   known-failing ("build must exit non-zero") so they turn green when §8.1 is fixed.
2. **Statistics golden tests** (`node:test`, no new deps): load
   `dist/standalone/odc-d3.js` with `require` and assert every value in §7.6,
   including the current exception for df ≤ 3 (marked as known defect).
3. **Utils unit tests** (`node:test`): `deepExtend` (nested merge, arrays
   replaced), `mergeDeep`, `nest`, `inferVariables` (group key excluded),
   `cross`, `isNumber/isDate/isString`, `createScale('linear'|'log'|'time')`,
   `createAxis('bottom'|'left')` and the error for unknown names.
4. **Export surface snapshot**: the 27 names of §7.1 for `src/index.js`,
   `dist/odc-d3.js` (with a global d3) and `dist/standalone/odc-d3.js`.
5. **Browser smoke** (minimum: Playwright + Chromium as a devDependency; not
   jsdom, because rendering depends on real SVG layout –
   `getComputedTextLength()` in `Utils.placeTextWithEllipsis`,
   `getBoundingClientRect()` in `CorrelationMatrix`, `getComputedStyle` in
   `Utils.getFontSize` – and mocked geometry would hide regressions; jsdom may
   be used only for separate non-rendering DOM tests):
   for each of the 12 chart classes, render inline deterministic data with
   default config in both bundles and assert: one `svg` with the expected
   `odc-*` class, expected count of marks (dots/bars/cells), no page errors,
   `destroy()` empties the container, and a second `init()` does not duplicate
   the `svg`. Use deterministic fixture data, not the random demos.
6. **Prototype extensions**:
   - `selectOrAppend('g.a.b#c')` creates `<g class="a b" id="c">` on the first
     call and returns the existing element on the second (no duplicate);
     `selectOrInsert(selector, before)` likewise, inserting before `before`.
   - `appendSelector('g.a.b#c')` and `insertSelector(selector, before)` are
     **not** idempotent: every call creates a new element with the parsed
     tag/classes/id. Two calls → two elements.
